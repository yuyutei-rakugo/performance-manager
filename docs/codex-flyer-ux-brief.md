# Codex 作業依頼：チラシ配布・掲示の登録と地図の操作改善

## 目的
年配のメンバーがスマホで、説明を読まなくても施設を登録でき、保存結果とピンの状態を確認できること。使用者として画面を操作するレビューまで実施する。

## 対象・着手状態

- リポジトリ：yuyutei-rakugo/performance-manager
- 作業前に main と作業ブランチの最新履歴を取得する。

## 合意した完成形
1. 普段は一覧。施設名・状況・「状況を変更」を中心にする。住所や名前の編集は分ける。
2. 一覧の検索は「登録済みの施設を探す」と明示し、「検索する」と Enter に対応する。入力済みの名前を再入力させない。
3. 一致がなくても未収録と断定しない。別名・表記違い・検索語違いを案内し、その名前で追加画面に進める。
4. 候補は名前と住所で選ぶ。地域データの別名、かな表記、名前の一部、複数語の順序違いも扱う。登録済みは区別し、勝手に統合しない。
5. 施設名と地域で登録完了。場所の設定は任意。検索結果や地図の通信待ちを登録の必須条件にしない。
6. 候補を選んだ場合は「この施設ですか？」で名前・住所・確認用の地図を表示。地図を押しただけでピンを動かさない。「場所を変更」から位置指定する。
7. 保存ボタンは画面下に一つ、スクロール中も見える。二重保存を防止し、失敗時は入力を保持する。
8. 保存後は施設を強調し、施設とピンが保存されたか、場所が未設定かを明示する。地図へ進めること。
9. 「場所の要確認 ○件」から未設定施設を確認できる。住所検索・Googleマップ検索・共有リンク・手動指定を任意で使用する。
10. リンク保存と座標設定を混同しない。座標を読めない短いリンクを保存しても要確認に残す。
11. 候補名と登録名が違えば両方を示し、本人の操作で名前を変更する。入力途中の名前変更で座標・状況・メモを失わない。Googleの表示名だけで自動変更しない。

## 必ず修正・確認する不具合
- 手動地図が長いオプション欄の下に出て、ボタンが無反応に見える。
- 同じ用途の地図ボタンが二つあり分かりにくい。
- 読み込み中・通信失敗・再試行を押した場所で認識できるか。
- 地図の背景取得失敗を無反応と誤解させないか。
- スマホ幅で登録ボタンや地図、エラー表示が隠れないか。

## 使用者レビューの手順と合格条件
- 360×740 と小さい画面で、入力・タップ・スクロールを行う。見た目はスクリーンショットも確認する。
- 一覧で未登録名を検索→追加。名前が引き継がれ、施設だけ保存できる。
- 要確認→短いリンクのみ保存。施設は残り、ピンが設定済みと誤表示されない。
- 候補を選択→地図を見る→登録。確認用地図へのタップで座標が動かない。
- 手動地図を開く・閉じる・再度開く。押した直後に反応し、すぐ近くに地図が見える。
- 地図をタップして位置指定→保存→地図でピンを確認。通信失敗も想定する。
- Google検索を開く操作は試験ページで確認し、メモ等の私的情報を検索URLへ渡さない。
- 名前の修正、保存失敗→再試行、変更破棄、登録済み候補の扱いを確認する。
- 試験用データだけで書き込みを検証し、本番メンバーの入力をテストで変更しない。

## 制約・報告
全体巻き戻し、メンバー入力の破棄、有料API契約・課金設定の追加、Google地図データの一括収集はしない。丸竹／マルタケとマルトモを混同しない。
実装→必要なテスト→使用者レビュー→問題修正→公開確認の順で完了する。確認済み・推定・未確認を区別し、公開前を公開済みと言わない。使用量が大きく増える作業は先に説明する。
